# GroundAnything: Reconciling Parallel Decoding with Precise Visual Grounding at Flash Speed

> **GroundAnything은 4B급 grounding VLM(박스·점 좌표를 출력하는 VLM)을 블록 단위 masked diffusion(마스크 확산) 디코더로 변환해서 좌표 토큰을 병렬로 뽑는 모델이다. 구조·손실·디코딩 규칙은 공개 코드와 정확히 일치하고(파라미터 수 바이트 단위 일치), DLM↔MTP 통제 실험은 정직하다. 그러나 대표 숫자 두 개가 흔들린다. ① 확산 모델이 자기 AR 부모를 이긴 지점(RefCOCOg +7, ScreenSpot-Pro +10.6, OSWorld-G +6.6)은 논문에 없는 DLM 전용 SFT2 단계와 겹치는데, 코드가 노출한 SFT2 소스 이름이 평가 벤치마크 키와 똑같고 행 수도 평가셋의 절반·전량과 맞는다(test contamination 강한 의심). RefCOCOg에서 IoU 0.95 F1이 88.6(COCO에선 22.4)이라는 이상치도 이것으로 설명된다. ② "2.56×/4.51× 빠르다"는 TPF(forward당 토큰) 1.37/2.18로는 설명이 안 되고, 나머지는 AR 기준과 DLM의 실행 스택 차이로 보인다.**

## 📖 주요 용어 사전 (Glossary)

### 문제 설정 · 평가

| 용어 | 풀이 |
|---|---|
| **visual grounding(시각 그라운딩)** | 말로 지정한 대상("빨간 컵", "person")을 이미지에서 박스나 점으로 찾아내는 일. 검출·지시표현·OCR·GUI 클릭 위치·레이아웃까지 "좌표를 출력"하는 태스크 전반 |
| **F1mIoU** | IoU(겹침 비율) 임계값 0.50, 0.55, …, 0.95 각각에서 F1을 구해 평균낸 값. "평균 IoU"가 아님. Rex-Omni 평가 관례를 따름 |
| **F1@0.95** | 예측 박스가 정답과 95% 이상 겹쳐야 정답으로 치는 F1. 사람이 친 정답 박스의 오차 수준이라 보통 20~40점대 |
| **F1@Point** | 점이 정답 물체의 SAM 마스크 안에 들어가면 정답으로 치는 F1 |
| **test contamination(평가셋 오염)** | 평가용 데이터가 학습에 섞여 들어가 점수가 부풀려지는 현상 |

### 모델 · 출력 형식

| 용어 | 풀이 |
|---|---|
| **quantized coordinate tokens(양자화 좌표 토큰)** | 0~999 좌표를 전용 토큰 `<0>`…`<999>` 1000개로 만들어 좌표 하나 = 토큰 하나. 박스 하나가 평균 7.6토큰 |
| **`None` payload** | 질의한 카테고리가 이미지에 없으면 박스 자리에 `None`을 쓰는 규약 |
| **untied embedding(분리된 임베딩)** | 입력 임베딩 행렬과 출력 head 행렬을 따로 두는 것. 원래 Qwen3-4B는 공유(tied)하지만 여기선 분리 → 0.39B씩 두 벌 |

### 디코딩

| 용어 | 풀이 |
|---|---|
| **AR (autoregressive, 자기회귀)** | 왼쪽부터 한 토큰씩 생성. GroundAnything-VLM의 방식 |
| **DLM (Diffusion Language Model, 확산 언어모델)** | 왼쪽부터 한 칸씩이 아니라 빈칸을 깔아 두고 여러 칸씩 채우는 언어모델. 이 논문에서는 GroundAnything 본체(↔ AR인 GroundAnything-VLM) → Q3 |
| **masked diffusion(마스크 확산)** | 노이즈 대신 토큰을 `[MASK]`로 가렸다가 다시 맞히는 확산. 가린 비율 t가 노이즈 세기 역할 → Q4 |
| **block diffusion(블록 확산)** | 출력을 B=32토큰 블록으로 자르고, 블록 안은 양방향(bidirectional) attention으로 병렬 채움, 블록 사이는 causal로 순서대로. KV cache 재사용 가능 |
| **TPF (tokens per forward)** | forward 한 번당 확정되는 토큰 수. AR은 1. 알고리즘적 가속의 상한 |
| **TPS (tokens per second)** | 초당 출력 토큰 수. 실제 속도(구현 영향 포함) |
| **entropy-guided decoding(엔트로피 기반 확정)** | 각 빈칸의 예측 분포 엔트로피(불확실성)가 τ 이하인 위치만 확정. 하나도 없으면 가장 확실한 한 칸만 확정 |
| **self-speculative decoding(자기 추측 디코딩)** | 같은 가중치로 확산 모드가 초안을 쓰고 causal 모드가 검증. 일치하는 가장 긴 앞부분만 수락 |
| **MTP (multi-token prediction)** | 한 forward로 여러 미래 토큰을 예측하는 헤드. LocateAnything이 사용 |
| **NFE (network function evaluation)** | 모델 forward 호출 횟수 |

### 학습

| 용어 | 풀이 |
|---|---|
| **AR-to-diffusion conversion(AR→확산 변환)** | 이미 학습된 AR 모델에 mask 토큰만 추가하고 확산 손실로 이어 학습해 확산 모델로 바꾸는 것. Fast-dVLM 방식 |
| **complementary masking(상보적 마스킹)** | 같은 응답에서 마스크 두 장을 만들되, 한 장에서 가린 위치는 다른 장에서 보이게 함 → 모든 토큰이 한 번은 학습됨 |
| **GRPO** | 프롬프트당 응답 G개를 뽑아 그룹 안에서 보상을 정규화해 advantage(상대적 이득)로 쓰는 RL. 가치망 불필요 |

## 🎯 논문 요약 (TL;DR)

- **한 줄**: grounding 출력(박스·점 좌표)은 왼쪽→오른쪽 순서가 본질이 아니니, AR VLM을 블록 확산으로 변환해 좌표를 병렬로 채우자.
- **문제**: AR grounding은 박스 수가 많을수록(밀집 장면, 문서 레이아웃) 출력이 길어지고, 토큰 하나당 forward 한 번이라 느리다.
- **해결**: Qwen3-4B 기반 grounding VLM을 만든 뒤(→ GroundAnything-VLM), 확산 0.5 + AR 0.5 손실로 변환(→ GroundAnything). 한 가중치가 확산 초안과 AR 검증을 모두 할 수 있음.
- **검증(주장)**: 30개 벤치 평균 VLM 72.42(GPT-6 Astra 71.35), DLM 61.75(LocateAnything Fast 53.32). COCO에서 entropy 디코딩 2.56×(−2.98pp), self-spec 4.51×(−0.74pp).
- **급소**: 평가셋 이름의 학습 소스(→ Q1), 속도 배수에 섞인 구현 차이(→ 3.2), 통제되지 않은 AR↔DLM 비교(→ 3.4).

*좌표 출력을 병렬로 채우려면 ① 좌표를 짧은 토큰으로 만들고 ② AR 모델을 확산으로 바꾸고 ③ 병렬로 확정할 규칙이 필요하다. 이 장은 그 세 가지를 순서대로 설명한다.*

### 1.1 전체 구조

*AR 모델과 확산 모델이 가중치를 그대로 공유해야 self-spec이 가능하므로, 둘은 같은 뼈대를 쓴다.*

![Fig.2](figures/groundanything_fig2.png)

| 부품 | 구성 | 파라미터 (HF 가중치 실측 = 논문 Table 9) |
|---|---|---|
| vision encoder(시각 인코더) | MoonViT-V2, 27층 × 1024폭, patch 14, 최대 1024 visual token | 401,214,464 |
| projector(연결층) | LayerNorm → 2×2 patch 묶음(1024×4=4096) → Linear 4096→4096 → GELU → Linear 4096→2560 → RMSNorm | 27,267,584 |
| LM decoder body | Qwen3-4B: 36층 × 2560, FFN 9728, GQA 32/8, RoPE base 5M, 전부 full attention, 1D RoPE | 3,633,511,936 |
| input embedding / output head | untied, 각 152,671행(DLM) × 2560 | 390,837,760 × 2 |
| **합계** | | **4,843,669,504 (DLM)** / 4,843,664,384 (VLM) |

- "4B"는 디코더 이름일 뿐이고 전체는 **4.84B**. 논문 Table 9가 스스로 밝힘.
- 어휘: Qwen3 기본 151,669 + 좌표 1000 + `</c>` = 152,670(VLM), DLM은 `|<MASK>|` 추가로 152,671. 각 토큰을 왜 추가했고 MASK 초기값을 어떻게 잡는지는 → Q2.
- DeepStack(ViT 중간층을 LLM 여러 층에 주입) 같은 다층 시각 주입은 **없음** (코드·가중치로 확인).

### 1.2 출력 문법

*검출·OCR·GUI처럼 서로 다른 태스크를 하나의 모델이 처리하려면 출력 형식이 하나여야 한다.*

```
<|object_ref_start|>person<|object_ref_end|><|box_start|><10><20><30><40>,<50><60><70><80><|box_end|>
<|object_ref_start|>button<|object_ref_end|><|box_start|><512><384><|box_end|>          ← 점
<|object_ref_start|>OPEN<|object_ref_end|><|box_start|><100><200><300><260><|box_end|>   ← OCR: 글자가 이름 칸
<|object_ref_start|>car<|object_ref_end|><|box_start|>None<|box_end|>                    ← 없는 대상
```

- 박스는 (x1,y1,x2,y2), 점은 (x,y). 같은 이름의 인스턴스는 한 wrapper에 쉼표로.
- 박스는 x1 기준 안정 정렬(stable sort), 궤적처럼 의미 있는 순서는 유지.
- 좌표 변환: 0~1000 격자 값 v를 `floor((999·v + 500) / 1000)`로 0~999 토큰에 매핑.
- 출력 길이: COCO 이미지당 46.4토큰(박스당 7.6), Dense200 446.8토큰(박스당 5.1). SEED1.5-VL은 박스당 148.8 (Table 5).

### 1.3 AR→확산 변환 (Conversion)

*확산 VLM을 처음부터 학습하면 이미지 보기·언어·좌표·출력 문법을 전부 다시 배워야 해서 비싸다. 그래서 이 모든 것을 이미 배운 AR grounding 모델의 가중치를 그대로 가져와 출발점으로 삼고, 바뀌는 세 가지(어휘에 `[MASK]` 1줄 추가, 빈칸 블록 안 양방향 attention, 빈칸 맞히기 손실)만 추가로 학습시킨다(continued training). 새로 생기는 가중치는 MASK 줄 하나뿐이다. 자세한 풀이는 → Q8.*

![Fig.4](figures/groundanything_fig4.png)

**입력 구성**: 한 시퀀스에 `[noisy view 1 ; noisy view 2 ; clean x]`를 이어 붙인다. clean x = [이미지 V, 프롬프트 P, 응답 Y]. noisy view = [프롬프트 복사본, 마스크 낀 응답]. 이미지는 clean 쪽에만 한 번 인코딩.

**마스킹** (코드 `models/dlm/hybrid.py:585-653`과 일치):
1. 응답을 32토큰 블록으로 자름(박스 경계와 무관).
2. 블록마다 t ~ Uniform(0,1) 뽑기 → 각 토큰을 확률 t로 가림 = view 1.
3. view 2 = view 1의 반대(가린 곳 ↔ 보인 곳). EOS는 두 view 모두 가림.

**attention mask** (그림 4, 코드 `hybrid.py:751-802`와 일치):
- noisy 블록 → 같은 블록 안은 양방향(보라).
- noisy 블록 → clean 이미지·프롬프트와 **자기보다 앞선** clean 응답 블록만 봄(연두).
- clean → causal(초록), noisy는 못 봄.

**손실** (코드 `hybrid.py:2142-2151`):

```
L = 0.5 · L_MDM + 0.5 · L_AR
```
(즉 "가려진 칸 맞히기" 손실과 "다음 토큰 맞히기" 손실을 반반 섞음. 둘 다 hidden i−1이 target i를 예측하는 next-token shift 유지. inverse-noise 가중치 없음)

**변환 학습 설정 (논문 Table 12 ↔ 코드)**:

| 항목 | 논문 | 공개 코드 `configs/training_stages.yaml` |
|---|---|---|
| 단계 | Phase I(vision 동결) → Phase II(전체) | general(2 ep) → specialist(2 ep) → **sft1(1 ep) → sft2(1 ep)** |
| GPU / global batch | 256 / 8192 | 64 / 2048 |
| LR | 2e-5 (vision 2e-6) | 같음. sft1/2는 7e-6 |
| seed | 32 / 42 | 같음 |
| 행 수 | 미기재 | 299만 / 3,000만 / 474만 / 30만 |

→ general/specialist가 Phase I/II에 해당. **sft1·sft2는 논문에 없는 DLM 전용 단계** (→ Q1, 3.4).

### 1.4 RL (Causal GRPO)

*변환 후 확산 모델의 좌표 정확도를 끌어올리기 위한 마지막 단계. 단, rollout은 확산이 아닌 causal(AR) 모드로 뽑는다.*

![Fig.5](figures/groundanything_fig5.png)

- 프롬프트당 응답 G=8, 온도 0.7, **causal 모드로 생성하고 causal 확률로 학습**. 확산 디코딩 경로 자체는 RL이 직접 최적화하지 않음 → 학습된 가중치를 확산 추론에 그대로 재사용.
- advantage: 보상 성분별로 그룹 정규화 → 가중합 → 다시 그룹 정규화. 박스는 set completeness 0.7 + strict localization 0.3.
- clip ε=0.2, KL 없음, vision 동결, rollout당 업데이트 1회.
- **VLM과 DLM의 RL 레시피가 다름** (Table 13):

| 설정 | GroundAnything (DLM) | GroundAnything-VLM |
|---|---|---|
| LR | 2e-6 | 5e-7 (4배 작음) |
| reference KL | 없음 | 0.02 |
| 학습 모듈 | projector + LM | LM만 |
| 정규화 | population std + 2차 그룹 정규화 | sample std + 배치 정규화 |

**보상 함수 핵심** (Appendix A.10):
- **Box set completeness**: GT마다 IoU 최대 예측을 골라 라벨 일치 시 IoU를 점수로 → soft P/R의 F1. 한 예측이 여러 GT를 지원할 수 있어 "완전성 대리지표".
- **Box strict**: 0.10 형식 + 0.10 개수 + 0.50 F1(IoU .5/.75/.95 평균) + 0.25 IoU + 0.05 정렬 − 0.07 과대박스 − 0.03 중복.
- **OCR**: Hungarian 일대일 매칭 + 편집거리 + IoU, 형식 등급(1.0/0.6/0.3/0)을 제곱해서 곱함.
- **Pointing**: 거리 75 단위 가우시안 유사도(200 넘으면 0), 0.55·F2 + 0.25 개수 + 0.10 라벨 F1 + 0.10 형식.

### 1.5 추론 — 세 가지 디코딩

*병렬로 채울 때 "어느 칸을 언제 확정할지"가 속도와 정확도를 가른다.*

**① entropy-guided (본문 표 전부 이 방식)**
- prefill 후 블록 = [알려진 anchor 1개 + mask 31개], sub-block 4칸씩 왼쪽부터.
- 각 mask 위치의 엔트로피를 계산(mask 토큰 제외, 온도 적용 전 원본 logit) → τ=0.8 이하 전부 확정, 없으면 최소 하나.
- 블록 완성 후 causal forward 1회로 KV cache를 다시 만들고 다음 anchor 예측. 블록당 NFE = 디노이징 횟수 + 1.
- 코드 `infer/decode/reliability.py:20-188`과 일치.

**② self-speculative (linear / quadratic)**

![Fig.6](figures/groundanything_fig6.png)

- **linear**: 확산 초안 1 forward + causal 검증 1 forward = 2 NFE. 가장 긴 일치 prefix 수락 + 첫 불일치에서 AR 교정 토큰. 코드 로직 정확 (`gam_speculative.py:416-438`).
- **quadratic**: B개 행 × (B+1) 토큰을 한 forward에 넣어 검증과 다음 초안을 동시에. NFE는 1이지만 query 토큰이 B(B+1)개라 B=32에서 오히려 느림(49.9 TPS). **공개 코드에 없음.**
- 검증기는 **변환된 모델의 causal 가지**이지 원래 VLM이 아님 → self-spec 결과가 VLM과 같다는 보장 없음 (논문도 인정, −0.74pp의 원인).

**③ dynamic / static**: confidence 임계값 / 고정 할당량 방식. 인프라 실험(Fig.15)에만 등장.

### 2.3 DLM vs MTP (통제 실험)

*"왜 MTP가 아니라 확산으로 초안을 쓰나?"에 답하는, 이 논문에서 가장 정직한 실험.*

같은 frozen causal 검증기, 같은 prefix 묶음에서 초안기만 교체:

| 지표 (K=16) | causal MTP (자체 구현) | DLM 1 step | DLM 2 step |
|---|---|---|---|
| 초안 수락률 | 16.8% | 21.8% | — |
| 수락 토큰/라운드 | 2.69 | 3.48 | — |
| 수락 토큰당 비용 | 7.71 ms | 5.38 ms | **4.70 ms** |

- 4·8 step은 오히려 비용 증가(6.84, 11.83 ms). K=4에서는 MTP가 더 쌈(7.15 vs 9.31 ms). 50ms 마감에선 MTP 승, 400ms 마감에선 DLM 승(97.1 vs 84.6 토큰).
- Dense200 빗나간 박스 비율: causal MTP 24.9% → causal DLM 21.7% → bidirectional DLM 14.8%. **양방향 block-MTP도 개선** → "양방향 attention의 이득이지 확산 고유의 이득은 아님"을 논문이 인정.

| 변경 | AR | DLM |

## 3️⃣ 비판적 평가 — 논문의 급소

*숫자를 액면 그대로 받기 전에 확인해야 할 지점들. 가장 중대한 것부터.*

### 3.1 ① RefCOCOg의 IoU 0.95 이상치 — 평가 정답을 본 흔적

*같은 모델이 이미지 출처에 따라 박스 정밀도가 4배 차이 나면, 모델 능력보다 데이터를 의심해야 한다.*

| 모델 | RefCOCOg val F1@0.5 | F1@0.95 | COCO F1@0.95 |
|---|---|---|---|
| **GA (DLM)** | 92.66 | **88.63** | 22.39 |
| GA-VLM | 94.11 | 51.46 | 23.87 |
| SenseNova-Vision | 89.94 | 43.58 | 28.61 |
| Qwen3.7-Max | 91.56 | 48.45 | 24.66 |
| GPT-6 Astra | 92.13 | 35.89 | 26.11 |

- DLM은 0.5에서 맞힌 박스의 **96%가 0.95에서도 맞음**. 다른 모든 모델은 절반 이하로 떨어짐.
- COCO(val2017, 학습 이미지와 분리)에서는 22.39로 평범. 같은 종류 물체·같은 COCO 박스 규격인데 4배 차이.
- 원인 후보: ⓐ RefCOCO 계열 이미지는 전부 COCO train2014 → COCO train 검출 라벨로 정답 박스를 봤을 가능성 ⓑ **더 직접적으로, 코드가 노출한 SFT2 소스에 `gam_refcocog_val`·`gam_refcocog_test`가 있음** (→ Q1).
- 같은 논문 안에 RefCOCOg 점수가 두 개: 표 19 val 91.61 vs 표 20 family 83.06. 코드상 데이터 경로가 다르지만(`refcocog_val.yaml` vs `refcocog_rexstyle_val.yaml`) 차이 설명 없음.
- 자기 모델 COCO/LVIS 행에 Zero-shot "YES" 표기 — 학습 데이터 목록 비공개 상태에서 검증 불가.

### 3.2 ② 속도 배수에 구현 차이가 섞여 있다

*TPF는 알고리즘이 줄인 forward 수다. TPS 배수가 TPF보다 훨씬 크면 나머지는 forward 1회 자체가 빨라진 것, 즉 구현 차이다.*

```
AR      : 1 / 49.6  TPS ≈ 20.2 ms per forward  (1토큰 forward)
entropy : 1.37 / 127.0 ≈ 10.8 ms per forward  (32토큰 블록 forward)
linear  : 2.18 / 223.8 ≈  9.7 ms per forward
```
(즉 1토큰짜리 AR forward가 32토큰 블록 forward보다 두 배 느리게 측정됨 → 서로 다른 실행 스택)

- 알고리즘만으로 기대할 상한은 entropy 약 1.4×, linear 약 2.2×. 논문이 내세운 2.56×/4.51×의 절반가량은 구현 몫.
- AR 기준 49.6 TPS를 어떤 스택(HF eager? SGLang?)으로 쟀는지 본문·부록 어디에도 없음. 논문은 "인프라 배수(Fig.15)와 곱하지 말라"고만 함.
- 공개 코드: CUDA Graph 강제 OFF(`serve_sglang.py:50`), FP8 없음, `--max-running-requests 1`(단일 스트림). → Fig.15 최고 속도 재현 불가.

### 3.3 ③ "기존 SOTA 53.32" 비교 대상 고르기

*30개 벤치 평균은 모델별 계산표가 없어 검증할 수 없다. 본문 표만으로 재계산해 본다.*

본문 Table 1~4의 27개 열 단순 평균(우리 계산):

| 모델 | 27열 평균 |
|---|---|
| GA-VLM | 71.3 |
| GPT-6 Astra | 70.8 |
| GA (DLM) | 65.9 (논문 30벤치 61.75와 불일치) |
| **Rex-Omni** | **58.7** |
| LocateAnything Hybrid | 55.9 (25열) |
| LocateAnything Fast | 49.9 (25열) |

- 초록은 가장 약한 LocateAnything **Fast**(MTP)를 "prior SOTA"로 대비. 본문 표 기준으론 Rex-Omni가 더 높음.
- 초록은 "prior state of the art"라 쓰고 본문은 "prior overall **AR** SOTA"라 씀 — LocateAnything은 AR이 아니라 MTP.

### 3.4 ④ AR ↔ DLM 비교가 통제되지 않았다

*"확산이 AR보다 낫다/못하다"를 말하려면 두 모델이 디코딩 방식 말고는 같아야 한다.*

- DLM에만 있는 것: 변환 4단계(그중 sft1·sft2는 논문에 없음), LR 4배·KL 없음·projector 학습하는 RL.
- 따라서 DLM이 AR을 이긴 RefCOCOg·GUI(+7~10pp)는 확산의 장점인지 추가 학습 데이터(→ Q1) 덕인지 구분 불가.
- "w/o Stage III"가 DLM에서만 −16.62pp → DLM 성능이 특정 후단계에 크게 의존한다는 뜻인데, 그 단계가 무엇인지 미공개.

### 3.5 ⑤ 논문에 없는 평가 시 처리

*같은 모델이라도 디코딩 설정과 후처리가 벤치마크마다 다르면 점수 해석이 달라진다.*

- **single-target truncation(단일 타깃 절단)**: referring·pointing·GUI 14개 태스크에서 확산 블록이 박스를 여러 개 내도 **첫 박스 하나만 남기고 강제 종료** (`infer/engines/sglang_gam/__init__.py:173-248`, 기본 ON). DLM 경로에만 적용. 단일 정답 벤치에서 precision을 올리는 효과.
- **벤치마크별 샘플링 등급** (`task_profiles.json`): strict_single T=0 / COCO·LVIS·레이아웃 T=0.1, top_p 0.95 / OCR T=0.3 등. 논문 미기재.
- "5 seed × 2회 = 10회 평균"이라 했지만 평가 코드는 seed 42 고정, 다회 집계 도구 없음.

### 3.6 ⑥ 사소한 것

- Fig.2에 "221B tokens pretrain", 부록 A.5에 "700B 토큰 이상" — 어느 단계 수치인지 불명.
- RL은 rollout당 업데이트 1회라 old/new 확률 비율이 항상 1 → clip은 실제로 작동 안 함(그룹 정규화 REINFORCE와 동일). 버그는 아니나 식(3)의 clip은 장식.
- "4B" = 디코더 기준, 전체 4.84B (논문 Table 9가 명시하므로 감점 작음).

### 4.3 버그·함정

- **DLM config 불일치**: `config.json`의 `vocab_size: 152670`인데 가중치는 152,671행 + 키에 `base_model.` 접두사 → `AutoModel.from_pretrained` 직접 로드 불가, 저장소 래퍼(resize 후 `strict=False`)로만 로드.
- **죽은 코드**: `models/vlm/streammind_gate.py`(Mamba + 4층 Qwen3 "말할까/말까" 분류기, 영상 프로젝트 잔재)가 모델 파일에 연결돼 있으나 가중치 없음. Qwen3.5 하이브리드(GatedDeltaNet)용 DLM 래퍼(`GAMQwen35DLM`)가 기반 클래스로 남아 있음 — 실제 백본은 Qwen3.
- **third_party**: 패치된 SGLang(v0.5.6.post2 기준 386개 파일 교체/추가), transformers(v5.7.0 기준 9개), lmms-eval(22개)를 tarball로 동봉. 패치는 해시만 기록돼 diff 검토 불가. transformers 버전 표기 3곳이 제각각(5.5.4 / 5.7.0 / 5.2.0).
- **평가 지표**: Rex-Omni 관례 그대로 — 이미지 안에서 **카테고리 무관(label-agnostic) 매칭**, F1은 데이터셋 평균 P·R의 조화평균. 모든 모델에 동일 적용이라 공정성 문제는 아니지만 "카테고리 맞히기"는 약하게 평가됨.
- **테스트**: 58개 전부 도구(배치 재개·데이터 확인·vLLM 계획). 모델·손실·디코딩·지표 테스트 0개.

### 4.4 미공개

- AR 사전학습·좌표 정렬(Stage 1~4), VLM용 RL(KL 0.02 레시피)
- quadratic self-spec, FP8, dynamic/static의 논문판 구현
- 학습 데이터, 원본 JSONL → Arrow 캐시 변환기
- sft1/sft2 데이터셋 목록 (config에서 삭제됨, RL 빌더 코드에만 이름이 남음 → Q1)

### 4.5 라이선스

- 코드 Apache-2.0. 모델은 Kimi K3 라이선스 승계(수정 MIT): 월 MAU 1억 또는 월매출 $20M 초과 제품은 "Kimi K3" 표기 의무, 연매출 $20M 초과 MaaS는 Moonshot과 별도 계약.

### 4.6 쓰기 전에 알 것

## 💬 Q&A

### Q1. 학습셋은?

*학습 데이터를 알아야 벤치 점수가 일반화 능력인지 암기인지 판단할 수 있다.*

#### ① 논문이 밝힌 것

- 데이터셋 이름 **0개**. "public datasets + data engine"만 서술.
- data engine: 여러 teacher 모델의 예측을 필드(박스/마스크/속성) 단위로 융합 → 태스크별 검증 → 통과한 라벨로 grounding expert 학습 → expert가 다시 라벨 제안(반복). teacher 모델 이름도 미공개. AI Use Statement에서 "generative AI 모델로 pseudo-label 생성" 인정.
- 사전학습 700B 토큰 이상(Fig.2엔 221B), 좌표 정렬(SFT)은 8개 태스크 그룹.

#### ② 공개 저장소가 밝힌 것

- 학습 데이터 자체 없음. DLM config에서 데이터셋 목록이 지워지고 행 수만 남음.

| DLM 단계 | 행 수 | 에폭 |
|---|---|---|
| general | 2,997,407 | 2 |
| specialist | 29,996,394 | 2 |
| sft1 | 4,739,428 | 1 |
| sft2 | 302,678 | 1 |

- 단서: `train/runtime/tar_uri.py`(OpenImages tar 경로), `header_only_cache.py` 주석("General Data V1 LLaVA inventory"), RL용 `lvis_grpo_gt20`, `ocr_mixed4583`.

#### ③ 결정적 단서 — RL 빌더가 노출한 SFT2 소스 이름

RL V3 데이터 빌더(`train/rl/shared/multiroute_data.py`의 `_quota()`)가 내부 sft2 목록에서 행을 뽑는데, 그 **소스 이름이 평가 벤치마크 키(`configs/datasets.yaml`)와 글자 하나 다르지 않다.**

| 학습 소스 (sft2 tier) | RL 사용 행 | 같은 이름 평가셋 크기 | 비고 |
|---|---|---|---|
| `gam_screenspot_v2` | 636 | 1,272 | **정확히 절반** |
| `gam_osworld_g` | 282 | 564 | **정확히 절반** |
| `gam_screenspot_pro` | 782 | 1,581 | 약 절반. 공개 train split 없는 벤치 |
| `gam_dense200` | 189 | 200 | 주석: "admissible Dense200 행을 전부 소비" |
| `gam_robospatial_context` | 122 | 122 (RoboSpatial-Home) | 전량 |
| `gam_refspatial_unseen` | 76 | 77 | 거의 전량 |
| `gam_refcocog_val` / `_test` | 250 / 300 | 4,889 / 9,577 | |
| `gam_rex_point_refcocog_val/test` | 500 / 700 | 4,887 / 9,572 | |
| `gam_visual_dense200`, `gam_fsc147` | 130 / 300 | 200 / 1,190 | |
| `gam_doclaynet`, `gam_m6doc`, OCR 4종, VisDrone, LVIS, COCO… | | | 30개 평가 묶음 전부 |

- `route_schema.py` 주석: *"RL 샘플링이 benchmark family를 통째로 빠뜨리지 않게"* — 학습 데이터 구성을 30개 평가 묶음 기준으로 설계.
- 논문 수치와의 정합: RoboSpatial context 72.13% = 88/122, RefSpatial Unseen 62.34% = 48/77 → 평가셋이 정확히 이 크기.

#### ④ 왜 심각한가

- sft2는 **DLM에만 있고 논문엔 아예 없는 단계**. DLM이 AR 부모를 이긴 지점(RefCOCOg +7, ScreenSpot-Pro +10.6, OSWorld-G +6.6, ScreenSpot-V2 +0.7)이 정확히 이 소스들과 겹침.
- 3.1의 RefCOCOg IoU 0.95 이상치(88.63)도 "평가 정답 박스를 학습에서 봤다"면 그대로 설명됨.
- 평가 config는 전량(1,272 / 564 등)을 평가 → 학습에 쓴 절반도 점수에 포함.

#### ⑤ 단서 (확정 못 하는 부분)

- 지워진 sft2 목록의 실제 행이 평가 파일 그 자체인지는 데이터가 없어 확정 불가. 같은 이름으로 만든 별도 학습용 분할일 가능성도 이론상 남음.
- 다만 ScreenSpot-Pro, OSWorld-G, Dense200, RoboSpatial-Home, RefSpatial-Bench는 **공개 train split이 없는 평가 전용 벤치**이고, 행 수가 평가셋의 절반·전량과 맞음 → test contamination 가능성 매우 높음.
- 이 RL V3 빌더가 논문 RL에 쓰였는지는 불명(공개 기본 RL은 2-source 레시피). 그러나 sft2 단계 자체는 공개 DLM 기본 학습 체인에 포함.

#### 요약

| 질문 | 답 |
|---|---|
| 논문에 학습셋 목록? | 없음 |
| 코드에 학습 데이터? | 없음 (config 목록도 삭제) |
| 평가셋 오염 증거? | DLM 전용 SFT2 소스 이름 = 평가 키, 행 수 = 평가셋 절반/전량 |
| 영향받는 점수 | RefCOCOg, ScreenSpot-Pro/V2, OSWorld-G, RoboSpatial, RefSpatial, Dense200 등 → 특히 DLM 쪽 |

### Q2. 어휘(vocabulary) 확장을 좀 더 직관적으로, 예를 들어 설명해줘

*좌표 토큰·칸막이·MASK 토큰이 왜 필요하고 어떻게 시작값을 잡는지 알아야 1.1절의 어휘 숫자가 이해된다.*

#### ① 어휘란?

모델은 글자를 직접 읽지 못하고, **번호가 붙은 토큰 목록**만 압니다. 이 목록이 어휘입니다. 토큰마다 다음 두 가지가 붙어 있습니다.
- **ID**: 몇 번째 토큰인지 나타내는 번호
- **embedding 행**: 그 토큰의 "뜻"을 담은 숫자 2560개. 커다란 표의 한 줄입니다.

Qwen3는 원래 토큰 151,669개(ID 0~151,668)를 알고 있습니다. 영어 단어 조각, 한자, 숫자, 특수기호 등입니다.

#### ② 좌표 토큰 1000개를 왜 추가했나

박스 좌표를 그냥 글자로 쓰면 낭비가 큽니다. 예를 들어 "컵이 (12, 220, 93, 352)에 있다"를 생각해 봅시다.

| 방식 | 출력 | 토큰 수 |
|:---|:---|:---|
| 글자로 쓰기 | `[`, `1`, `2`, `,`, `2`, `2`, `0`, `,`, `9`, `3`, `,`, `3`, `5`, `2`, `]` | 15개 (Qwen은 숫자를 한 자리씩 쪼갬) |
| 좌표 토큰 | `<12>`, `<220>`, `<93>`, `<352>` | 4개 |

- 그래서 `<0>`부터 `<999>`까지 **좌표 전용 토큰 1000개**를 만들어 ID 151,669~152,668을 붙였습니다.
- 이미지 너비를 1000칸으로 나눴을 때 37.3% 지점이면 `<373>` 한 토큰이 됩니다.
- 토큰 하나가 "x좌표 373"이라는 완결된 의미를 가지니, 모델이 "3 다음에 7…"처럼 자릿수를 이어 붙일 필요가 없습니다.
- 확산 모델에서는 이 차이가 더 큽니다. 빈칸 4개만 채우면 박스가 하나 완성되기 때문입니다. 논문 ablation에서 좌표 토큰을 글자로 바꾸면 DLM 점수가 5.68점 떨어졌습니다(2.4절).

#### ③ `</c>` 한 개를 왜 추가했나

여러 카테고리를 한 번에 물을 때 이름 사이를 구분하는 칸막이입니다.

```
Locate all the instances that match: person</c>hot dog</c>traffic light
```

쉼표나 공백을 칸막이로 쓰면 "hot dog"이 "hot"과 "dog" 두 개로 읽힐 수 있습니다. 쉼표가 들어간 이름도 있습니다. 이름 안에 절대 나올 리 없는 전용 토큰(ID 152,669)을 쓰면 헷갈릴 일이 없습니다.

**→ VLM 어휘 합계: 151,669 + 1,000 + 1 = 152,670개 (ID 0~152,669)**

#### ④ 확산 모델은 `|<MASK>|` 한 개를 더 추가

확산 디코딩은 "빈칸 채우기 게임"이라서, **"여기는 아직 모름"을 뜻하는 토큰**이 필요합니다.

```
처음:    <|box_start|> [MASK] [MASK] [MASK] [MASK] <|box_end|>
1회 후:  <|box_start|> <12>   [MASK] [MASK] <352>  <|box_end|>   ← 확실한 칸부터 확정
2회 후:  <|box_start|> <12>   <220>  <93>   <352>  <|box_end|>
```

- 이 토큰이 ID 152,670으로 추가되어 **DLM 어휘는 152,671개**가 됩니다.
- MASK는 입력에만 쓰입니다. 출력 후보에서는 잘라내서 모델이 "MASK"를 답으로 내는 일이 없습니다.

#### ⑤ 새 MASK 줄의 초기값을 왜 "네 토큰의 평균"으로 했나

새 토큰은 학습된 적이 없으니 embedding 줄을 어떤 값으로 시작할지 정해야 합니다.

- **무작위 값으로 시작하면:** 기존 15만 개 토큰 사이에서 엉뚱한 위치에 놓인 이방인이 됩니다. 학습 초반에 모델이 이 토큰을 보고 크게 흔들릴 수 있습니다.
- **평균으로 시작하면:** 다음 네 토큰의 embedding을 평균냅니다.
  - `<|im_start|>`: 대화 한 턴의 시작
  - `<|im_end|>`: 대화 한 턴의 끝
  - `<|vision_start|>`: 이미지 시작
  - `<|vision_end|>`: 이미지 끝

  네 토큰의 공통점은 **"내용이 아니라 구조를 표시하는 기호"**라는 것입니다. 그 평균에서 출발하면 MASK는 처음부터 "단어나 좌표가 아닌 표시용 기호" 근처에 놓입니다.
- **비유:** 새 직원 자리를 아무 데나 두지 않고, 비슷한 일을 하는 부서 한가운데 두는 것과 같습니다.

세부 사항:
- 평균은 정밀도 손실을 막기 위해 FP32로 계산한 뒤 모델 dtype(bf16)으로 바꿉니다.
- 이 모델은 입력 embedding 표와 출력 head 표를 따로 둡니다(untied). 그래서 두 표에 각각 한 줄씩, 2 × 2560 = **5,120개 파라미터**가 늘어납니다.
- 두 표의 역할은 다릅니다.
  - **입력 줄:** 이 토큰을 "읽을 때" 쓰는 뜻
  - **출력 줄:** 이 토큰을 "답으로 고를 때" 쓰는 채점 기준. MASK는 답으로 내지 않으므로 출력 줄은 사실상 쓰이지 않습니다.

#### 한눈에

| 범위 | ID | 개수 | 역할 |
|:---|:---|:---|:---|
| Qwen3 원래 토큰 | 0 ~ 151,668 | 151,669 | 일반 텍스트·특수 토큰 |
| 좌표 `<0>`~`<999>` | 151,669 ~ 152,668 | 1,000 | 좌표 하나 = 토큰 하나 |
| `</c>` | 152,669 | 1 | 카테고리 이름 칸막이 |
| `\|<MASK>\|` (DLM만) | 152,670 | 1 | 확산의 "빈칸" |

**참고:** 4.3절의 config 버그가 바로 이 마지막 한 줄입니다. 확산 모델 `config.json`에는 어휘 크기가 152,670으로 적혀 있는데, 실제 가중치는 MASK를 포함한 152,671줄이라 일반 로더로는 열리지 않습니다.

### Q3. DLM이란?

*논문 전체가 "VLM(AR) vs DLM" 대비로 쓰여 있어서, DLM이 무엇인지부터 잡아야 표를 읽을 수 있다.*

**DLM = Diffusion Language Model(확산 언어모델)**입니다. 이 논문에서는 확산 방식으로 출력하는 **GroundAnything 본체**를 가리킵니다. 반대편인 **GroundAnything-VLM**은 일반적인 AR(자기회귀) 모델입니다.

#### ① 두 모델의 차이: 답을 "쓰는 방식"

같은 질문 "컵 찾아줘"에 대한 정답이 `cup <12> <220> <93> <352>`라고 해 봅시다.

**AR 모델(GroundAnything-VLM)은 왼쪽부터 한 칸씩 씁니다.**
```
1번째 forward:  cup
2번째 forward:  cup <12>
3번째 forward:  cup <12> <220>
4번째 forward:  cup <12> <220> <93>
5번째 forward:  cup <12> <220> <93> <352>
```
- 토큰 5개 = 모델 호출 5번.
- 앞 글자를 써야 다음 글자를 쓸 수 있습니다. 사람이 펜으로 글을 쓰는 방식입니다.

**DLM(GroundAnything)은 빈칸을 한꺼번에 깔아 놓고 확실한 칸부터 채웁니다.**
```
시작:           [MASK] [MASK] [MASK] [MASK] [MASK]
1번째 forward:  cup    <12>   [MASK] [MASK] <352>     ← 자신 있는 3칸 동시 확정
2번째 forward:  cup    <12>   <220>  <93>   <352>     ← 나머지 2칸 확정
```
- 토큰 5개 = 모델 호출 2번.
- 순서와 상관없이 쉬운 칸부터 채웁니다. 시험지에서 아는 문제부터 푸는 것과 같습니다.
- (단순화한 그림입니다. 실제로는 `cup`이 앵커로 먼저 정해지고, 4칸짜리 창 안에서만 순서를 고릅니다 → Q7)

#### ② "확산(diffusion)"이라는 이름이 붙은 이유

이미지 생성 모델(Stable Diffusion 등)은 "노이즈로 가득한 그림 → 조금씩 깨끗하게"를 반복합니다. 텍스트에서는 노이즈 대신 **[MASK](빈칸)**를 씁니다. "빈칸투성이 문장 → 조금씩 채워 완성"이 같은 원리라서 확산이라는 이름이 붙었습니다(자세한 것은 Q4).

#### ③ 이 논문에서 DLM을 만드는 법

처음부터 따로 만들지 않고 **AR 모델을 개조**했습니다.
1. GroundAnything-VLM(AR)을 먼저 완성합니다.
2. 같은 가중치에 `[MASK]` 토큰만 추가합니다. Q2의 ID 152,670 토큰입니다.
3. "빈칸 채우기" 연습을 추가로 시킵니다. 이것이 AR→확산 변환(1.3절)이고, 결과물이 GroundAnything(DLM)입니다.

그래서 DLM 하나가 두 가지 모드를 다 할 수 있습니다. 하나는 빈칸을 병렬로 채우는 확산 모드이고, 다른 하나는 원래처럼 한 칸씩 쓰는 AR 모드입니다. self-speculative decoding은 이 성질을 이용합니다. 확산 모드로 초안을 빠르게 쓰고, AR 모드로 검산합니다.

#### ④ 왜 굳이 DLM을 쓰나: 속도

박스가 100개인 밀집 장면이면 출력이 수백 토큰입니다. AR은 수백 번 호출해야 하지만, DLM은 한 번에 여러 칸을 채우니 호출 횟수가 줄어듭니다.

그 대가로 정확도는 조금 떨어집니다. 30개 벤치 평균이 AR 72.42, DLM 61.75입니다. 3.2절에서 짚었듯이, 논문이 말하는 속도 배수의 절반가량은 알고리즘이 아니라 실행 환경 차이였습니다.

### Q4. 여기서 확산 모델이란?

*"확산"이라는 말이 이미지 생성의 노이즈 확산과 같은 뜻인지 헷갈리기 쉬워서, 이 논문의 확산이 정확히 무엇인지 정리한다.*

**한 줄 답:** 이 논문의 확산은 그림 생성 모델처럼 노이즈를 섞는 확산이 아닙니다. **토큰을 [MASK]로 가렸다가 다시 맞히는 "마스크 확산(masked diffusion)"**입니다.

#### ① 원조: 이미지 확산 모델

확산은 원래 이미지 생성에서 나온 개념입니다. 두 방향의 과정이 있습니다.

| 과정 | 하는 일 | 예 |
|:---|:---|:---|
| 망가뜨리기 (forward process) | 깨끗한 사진에 노이즈를 조금씩 섞음 | 고양이 사진 → 약간 지글지글 → 많이 지글지글 → 완전 모래알 |
| 되돌리기 (reverse process) | 모델이 노이즈를 조금씩 걷어냄 | 모래알 → 형체 → 고양이 |

- 학습 때는 "노이즈가 이만큼 섞인 사진에서 원본을 맞혀라"를 반복합니다.
- 생성할 때는 완전한 노이즈에서 출발해 되돌리기를 여러 번 합니다.

#### ② 텍스트 버전: 노이즈 대신 [MASK]

토큰은 `<12>`, `cup` 같은 **이산값(discrete)**이라 "약간 지글지글한 `<12>`" 같은 상태가 없습니다. 그래서 노이즈를 섞는 대신 **토큰을 [MASK]로 가리는 것**을 "망가뜨리기"로 씁니다. 가리는 비율 t가 노이즈 세기 역할을 합니다.

정답이 `cup <12> <220> <93> <352>`일 때:

| t (가림 비율) | 망가진 상태 |
|:---|:---|
| 0 | `cup <12> <220> <93> <352>` (원본) |
| 0.4 | `cup [MASK] <220> [MASK] <352>` |
| 0.8 | `[MASK] [MASK] <220> [MASK] [MASK]` |
| 1.0 | `[MASK] [MASK] [MASK] [MASK] [MASK]` (완전히 지워짐) |

이미지 확산과 짝을 맞추면 이렇습니다.

| | 이미지 확산 | 마스크 확산 (이 논문) |
|:---|:---|:---|
| 망가뜨리기 | 가우시안 노이즈 섞기 | 토큰을 [MASK]로 가리기 |
| 망가진 정도 | 노이즈 세기 | 가린 비율 t |
| 모델이 하는 일 | 노이즈 제거 | 빈칸에 들어갈 토큰 맞히기 |
| 생성 출발점 | 완전한 노이즈 | 전부 [MASK] |

#### ③ 학습: 빈칸 맞히기 시험을 무한 반복

1. 정답 문장을 하나 가져옵니다.
2. t를 무작위로 뽑습니다. 예를 들어 t = 0.6.
3. 토큰마다 60% 확률로 [MASK]로 가립니다.
4. 모델이 가려진 칸의 원래 토큰을 맞히고, 틀린 만큼 손실을 받습니다.

t가 매번 달라서 "거의 다 보이는 쉬운 문제"부터 "거의 다 가려진 어려운 문제"까지 골고루 연습합니다. 그래서 생성할 때 "전부 빈칸"에서 출발해도 풀 수 있습니다. (이 논문은 여기에 상보적 마스크 두 장 + AR 손실을 더함 → 1.3절)

AR 모델과 결정적으로 다른 점은 **빈칸이 양쪽을 다 본다는 것(bidirectional attention)**입니다.
- AR 모델은 `<93>`을 맞힐 때 왼쪽(`cup <12> <220>`)만 봅니다.
- 마스크 확산은 오른쪽의 `<352>`도 봅니다. "x2가 352니까 x1은 그보다 작겠지" 같은 추론이 가능합니다.

#### ④ 생성: 전부 빈칸 → 확실한 칸부터 확정

```
0회:  [MASK] [MASK] [MASK] [MASK] [MASK]
1회:  cup    <12>   [MASK] [MASK] <352>    ← 엔트로피(불확실성)가 낮은 칸만 확정
2회:  cup    <12>   <220>  <93>   <352>    ← 확정된 칸을 단서로 나머지 채움
```

- 한 번 확정한 칸은 다시 바꾸지 않습니다.
- 몇 칸을 한 번에 확정할지는 임계값 τ로 조절합니다. τ가 크면 과감하게 많이 채워 빠르지만 틀리기 쉽고, 작으면 신중하게 채워 느리지만 정확합니다. 논문은 τ = 0.8을 씁니다.

#### ⑤ 이 논문만의 변형: 블록 확산(block diffusion)

출력 전체를 한꺼번에 빈칸으로 만들면 문제가 생깁니다. 박스가 100개면 출력이 수백 토큰인데, 그 전체를 매번 다시 계산해야 합니다. 그래서 **32토큰씩 블록으로 잘라 블록 단위로 진행**합니다.

```
블록1 [32칸] → 확산으로 다 채움 → 확정, 저장(KV cache)
블록2 [32칸] → 블록1을 참고하며 확산으로 채움 → 확정, 저장
블록3 ...
```

- **블록 안:** 확산. 32칸이 서로 양방향으로 보며 병렬로 채워집니다.
- **블록 사이:** AR. 앞 블록이 끝나야 다음 블록을 시작합니다.

**비유:** 시험지를 한 페이지씩 풉니다. 한 페이지 안에서는 아는 문제부터 순서 없이 풀고, 페이지는 앞에서부터 넘깁니다. 이렇게 하면 앞 페이지 계산 결과를 저장해 두고 재사용할 수 있어서 긴 출력도 감당할 수 있습니다.

#### 정리

| 질문 | 답 |
|:---|:---|
| 무엇을 망가뜨리나? | 토큰을 [MASK]로 가림 (노이즈 아님) |
| 모델이 배우는 것 | 가려진 칸의 원래 토큰 맞히기 |
| 생성 방식 | 전부 빈칸에서 출발해 확실한 칸부터 여러 개씩 확정 |
| AR 대비 장점 | 한 번에 여러 토큰 확정(빠름), 빈칸이 오른쪽 문맥도 봄 |
| 이 논문의 형태 | 32토큰 블록: 블록 안은 확산, 블록 사이는 AR |

### Q5. 이 연구에서 DLM 방법의 장점은?

*AR 대비 정확도를 잃으면서까지 DLM을 쓸 가치가 어디에 있는지, 논문 근거로 확인되는 것과 아닌 것을 가른다.*

**요약:** 논문 근거로 확인되는 장점은 크게 다섯 가지입니다. 다만 대부분 "조건부" 장점이고, 정확도 자체는 AR보다 낮습니다.

#### ① 모델 호출 횟수가 줄어든다 (속도)

*AR은 토큰 1개당 forward 1번이지만, DLM은 1번에 여러 토큰을 확정합니다.*

| 방식 | forward 1번에 확정되는 토큰 (TPF) | COCO 정확도 |
|:---|:---|:---|
| AR (GA-VLM) | 1.00 | 63.70 |
| DLM entropy τ=0.8 | 1.37 | 60.72 |
| DLM + self-spec (linear) | 2.18 | 62.96 |

- **출력이 길수록 이득이 커집니다.** 박스 수별 생성 시간을 비교한 그림 17에서, 박스가 많은 이미지일수록 AR 대비 절약 시간이 커집니다. 밀집 장면(Dense200 이미지당 447토큰)이나 문서 레이아웃이 DLM이 노리는 시장입니다.
- **한계:** 알고리즘만으로 얻는 가속은 약 1.4~2.2배입니다. 논문이 말하는 2.56배·4.51배의 나머지는 실행 환경 차이입니다(3.2절).

#### ② 빈칸이 "오른쪽"도 본다 → 구조화된 출력에 유리

*박스 좌표 4개와 여러 물체는 서로 얽혀 있어서, 양쪽 문맥을 보면 덜 틀립니다.*

- 예를 들어 `<12> [?] <93> [?]`라면, x2=93을 보고 "x1은 93보다 작다", y2를 보고 "y1은 그보다 위"라는 식으로 추론할 수 있습니다. AR은 왼쪽만 봅니다.
- **근거:** 같은 검증기와 같은 조건에서 초안 품질을 비교했습니다(그림 14).

| 지표 | causal MTP | DLM (양방향) |
|:---|:---|:---|
| COCO 형식 오류 (괄호·좌표 개수 깨짐) | 5.01% | 1.80% |
| Dense200 빗나간 박스 비율 | 24.9% | 14.8% |
| DocLayNet 빗나간 박스 비율 | 개선 폭 7.5pp | |
| GUI (박스 1개) | 개선 폭 0.46pp뿐 | |

- 개선은 **여러 요소가 공간적으로 얽힌 곳(밀집·문서)에서 크고, 단일 대상(GUI)에서는 거의 없습니다.** "grounding은 서로 연결된 증거를 함께 채우는 일"이라는 논문 주장과 맞는 결과입니다.
- **한계:** 양방향 block-MTP도 개선됩니다. 이득의 본질은 "확산"보다 "양방향 attention"이고, 논문도 이를 인정합니다.

#### ③ MTP보다 초안을 싸게 만든다

*AR을 빠르게 하는 경쟁 방법인 MTP(여러 토큰 동시 예측 헤드)와 직접 비교한 결과입니다.*

| 지표 (후보 16토큰) | causal MTP | DLM 1회 | DLM 2회 다듬기 |
|:---|:---|:---|:---|
| 라운드당 수락 토큰 | 2.69 | 3.48 | — |
| 수락 토큰 1개당 비용 | 7.71 ms | 5.38 ms | **4.70 ms** |

- **고쳐 쓰기(refinement)가 됩니다.** MTP는 한 번 예측하면 끝이지만, DLM은 자신 없는 칸을 다시 가리고 한 번 더 맞힐 수 있습니다. 2회까지는 이득이고, 4회부터는 오히려 손해입니다.
- **시간 예산이 넉넉하면 유리합니다.** 400ms 안에 DLM은 97.1토큰, MTP는 84.6토큰을 확정합니다.
- **한계:** 50ms처럼 아주 짧은 예산이나 후보 길이 4에서는 MTP가 이깁니다.

#### ④ 속도와 정확도를 손잡이 하나로 조절

*같은 모델로 상황에 따라 "빠르게"와 "정확하게"를 바꿀 수 있습니다.*

| τ | 0.2 | 0.6 | 0.8 | 1.0 | 1.2 |
|:---|:---|:---|:---|:---|:---|
| 속도 (TPS) | 107 | 118 | 127 | 134 | 149 |
| COCO | 59.97 | 59.82 | **60.72** | 54.06 | 56.14 |

- 재학습 없이 추론 설정 하나로 조절합니다. 논문은 이를 LLM의 thinking effort에 비유합니다.
- **한계:** τ 0.8을 넘으면 정확도가 급락합니다. 안전하게 쓸 수 있는 구간이 좁습니다.

#### ⑤ 가중치 하나로 "초안 작성자 + 검산자"

*speculative decoding은 보통 작은 초안 모델을 따로 둬야 하는데, DLM은 자기 자신이 둘 다 합니다.*

- 확산 모드로 32칸 초안을 쓰고, 같은 가중치의 AR 모드로 검산합니다. 맞는 앞부분만 수락합니다.
- 추가 모델, 추가 메모리, 별도 학습이 필요 없습니다. 0.5 확산 + 0.5 AR 손실로 두 모드를 함께 학습한 덕분입니다.
- **결과:** COCO −0.74pp로 AR과 거의 같은 품질에, 알고리즘 기준 약 2.2배(TPF) 빠릅니다.
- **한계:** 검산자가 원래 VLM이 아니라 변환된 모델의 AR 모드라서 출력이 VLM과 똑같다는 보장은 없습니다.

#### 반대로, 장점이 아닌 것

| 주장처럼 보이지만 | 실제 |
|:---|:---|
| "DLM이 AR보다 정확하다" (RefCOCOg 91.6, ScreenSpot-Pro 76.0) | DLM 전용 학습 단계(sft2)에 평가셋 이름의 데이터가 들어 있어 오염 의심(Q1). 확산의 장점으로 보기 어려움 |
| "모든 태스크에 쓸 만하다" | OCR·레이아웃은 AR 대비 큰 손실 (SROIE 71.2 → 43.6, DocLayNet 85.8 → 68.4) |
| "2.56배·4.51배 빠르다" | 알고리즘 몫은 약 1.4배·2.2배, 나머지는 실행 스택 차이 |

#### 한 줄 정리

DLM의 진짜 장점은 **"박스가 많고 서로 얽힌 긴 출력에서, 양방향으로 보면서 여러 칸을 한 번에(그리고 고쳐 가며) 채우고, 같은 가중치로 검산까지 하는 것"**입니다. 반대로 단일 박스, OCR 글자, 아주 짧은 시간 예산에서는 이점이 작거나 오히려 손해입니다.

### Q6. DLM을 택한 이유는?

*방법의 장점(Q5)과 별개로, 저자들이 왜 하필 이 길을 골랐는지를 알면 논문의 주장과 한계를 함께 읽을 수 있다.*

**요약:** 논문이 직접 밝힌 이유는 네 가지이고, 정황상 추정되는 배경이 세 가지 더 있습니다.

#### 논문이 밝힌 이유

**① 과제 성격: grounding에는 "정해진 순서"가 없다** — 논문의 출발점이자 제목의 핵심 주장입니다.

- 저자들의 관찰은 이렇습니다. 사람은 사진 속 물체를 보는 순서가 매번 달라도 "무엇이 어디 있다"는 결론은 같습니다.
- 그런데 AR은 출력을 왼쪽부터 한 줄로 늘어놓도록 강제합니다.

```
<person> <10><20><30><40>, <50><60><70><80>  <car> <15><25><35><45>
```

- 사람이 차보다 먼저 나오는 데는 아무 의미가 없습니다. 박스는 x1 기준으로 정렬했을 뿐입니다. 그런데도 AR은 "사람 박스를 다 써야 차 박스를 쓸 수 있는" 줄 세우기를 합니다.
- 논문은 grounding을 **"visual evidence extraction(시각 증거 추출)"**으로 봅니다. 모든 좌표가 같은 이미지라는 증거에 동시에 묶여 있으니, 순서 없이 함께 채우고 서로 맞춰 보는 방식이 자연스럽다는 것입니다. 그 도구가 양방향으로 빈칸을 채우는 마스크 확산입니다.

**② 밀집 장면에서 AR이 너무 느리다** — 실용적인 동기입니다.

- 출력 길이는 COCO가 이미지당 약 46토큰이지만 Dense200은 약 447토큰입니다. 박스 수에 비례해 AR의 forward 횟수가 늘어납니다.
- 논문은 "latency-sensitive real-world systems(지연에 민감한 실제 시스템)"을 목표로 명시합니다.

**③ 경쟁 방법인 MTP보다 낫다 (LocateAnything 대비)** — 같은 문제("AR이 느리다")를 MTP로 푼 직전 연구 LocateAnything이 있었기 때문에, "왜 MTP가 아니라 확산인가"를 따로 증명했습니다.

| | MTP (LocateAnything 방식) | DLM (본 논문) |
|:---|:---|:---|
| 병렬 단위 | 박스 1개(6토큰)씩 | 32토큰 블록 (박스 여러 개를 가로지름) |
| 다시 고치기 | 불가 | 자신 없는 칸을 다시 가리고 재예측 |
| 초안 수락 토큰당 비용 | 7.71 ms | 4.70 ms (2회 다듬기) |
| 검증 모드 | 별도 헤드 필요 | 같은 가중치의 AR 모드로 검산 |

- MTP는 "박스 안 4좌표"만 함께 예측합니다. DLM은 블록 안의 여러 박스가 서로를 보며 채워집니다. 그래서 박스 사이의 관계(겹침, 중복)까지 반영할 수 있다는 논리입니다.

**④ 기존 AR 모델을 버리지 않아도 된다** — 처음부터 확산 모델을 만들 필요가 없습니다.

- 논문 Takeaway 2: "확산은 Transformer 백본 위의 **생성 전략**일 뿐이다."
- 잘 만든 AR grounding 모델에 [MASK] 토큰 하나를 추가하고 빈칸 채우기를 이어서 학습하면 확산 모델이 됩니다(AR→확산 변환, Fast-dVLM 방식).
- 결과적으로 AR 모드가 살아 있어 검산자로 재사용할 수 있고(self-speculative), AR 버전(VLM)도 함께 출시할 수 있었습니다.

#### 따져볼 점: 택한 이유와 결과가 맞아떨어졌나

| 주장한 이유 | 결과 |
|:---|:---|
| 순서 없는 과제라 확산이 자연스럽다 | 부분 확인. 밀집·문서에서 초안 품질이 좋아짐. 단 양방향 block-MTP도 개선되므로 "확산"보다 "양방향"의 덕 |
| 밀집 장면에서 빠르다 | 알고리즘 몫 약 1.4~2.2배. 홍보된 2.56·4.51배의 나머지는 실행 환경 차이 |
| MTP보다 낫다 | 자체 구현 MTP 대비 확인. 짧은 시간 예산에서는 MTP 승 |
| 정확도 유지 | 순수 확산 디코딩은 30벤치 평균 −10.7pp. OCR·레이아웃 손실 큼 |

#### 한 줄 정리

**"grounding 출력에는 본질적인 순서가 없으니, 양방향으로 여러 칸을 동시에 채우는 확산이 AR(느림)과 MTP(박스 단위에 갇힘)보다 과제 구조에 맞는다"**가 논문의 논리입니다. 여기에 저자 그룹이 이미 가진 AR→확산 변환 레시피와 저지연 수요가 실질적인 배경으로 보입니다.

### Q7. 확정 순서가 랜덤이 아니고 이런 식이면 사실상 오토리그레시브 방식 아냐?

*Q3·Q4의 예시(확신 높은 칸부터 확정)를 보면 "결국 AR과 뭐가 다르냐"는 의문이 자연스럽다. 이 논문 설정에서 실제 동작이 어디쯤인지 정리한다.*

**짧은 답: 반은 맞습니다.**
- 확정 순서는 **랜덤이 아니라 모델의 확신도 순**입니다.
- 그런데 이 논문 설정에서는 그 순서가 **AR(왼쪽→오른쪽)에 꽤 가깝게 묶여 있습니다.** 정확히는 "반(半)자기회귀(semi-autoregressive)"입니다.

#### ① 랜덤인 것과 랜덤이 아닌 것

| 단계 | 순서 | 설명 |
|:---|:---|:---|
| **학습** | 랜덤 | 블록마다 비율 t를 뽑고 토큰마다 확률 t로 [MASK]를 칩니다. 어느 칸이 가려질지 완전히 무작위 |
| **추론** | 랜덤 아님 | 매 forward마다 빈칸들의 엔트로피(불확실성)를 재고, τ=0.8 이하인 칸만 확정 |

학습을 랜덤으로 하는 이유는 "어떤 칸이 비어 있어도 맞힐 수 있는" 모델을 만들기 위해서입니다. 추론을 랜덤으로 하지 않는 이유는 랜덤으로 확정하면 자신 없는 칸이 먼저 굳어서 품질이 크게 떨어지기 때문입니다. 확산 언어모델 전반에서 알려진 현상입니다.

#### ② 세 가지 순서 방식 비교

| 방식 | 누가 순서를 정하나 | 한 번에 확정하는 수 |
|:---|:---|:---|
| 랜덤 unmasking | 주사위 | 정해진 개수 |
| **AR** | 규칙: 항상 맨 왼쪽 빈칸 | 1개 |
| **entropy-guided (이 논문)** | 모델이 매번 판단: 확신 높은 칸부터 | 0~여러 개 (최소 1개 보장) |

AR과의 핵심 차이는 **"순서가 고정이냐, 매번 모델이 고르냐"**입니다.

#### ③ 그런데 이 논문은 왜 AR에 가까운가 — 장치 세 개

**블록은 왼쪽부터 순서대로 (32토큰).** 블록1이 다 끝나야 블록2를 시작합니다. 블록 사이는 완전히 AR입니다.

**블록 안에서도 sub-block 4칸씩 왼쪽부터.** 논문 부록 B.1에 "Sub-blocks are completed from left to right"라고 명시돼 있습니다. 32칸 블록이라도 실제로 순서를 고를 수 있는 범위는 **지금 활성화된 4칸 안**뿐입니다.

```
블록(32칸): [앵커][M M M M][M M M M][M M M M] ... 
             ↑     ↑ 지금 여기 4칸만 확정 대상
                          ↑ 이 4칸은 앞 4칸이 다 끝나야 시작
```

**실제 측정값: forward 1번에 평균 1.37토큰.** τ=0.8 기준 TPF 1.37이고, AR은 1.0입니다. 즉 **대부분의 forward에서 1칸만 확정**되고, 가끔 2~3칸이 동시에 확정되는 수준입니다. 실제 동작은 "가끔 몇 칸을 묶어서 건너뛰는 AR"에 가깝습니다.

#### ④ 그래도 AR과 다른 점

**4칸 안에서는 순서가 자유롭습니다.** Q3·Q4의 예시를 정확히 고치면 이렇습니다. `cup`은 모델이 새로 채우는 칸이 아니라, 앞 단계에서 이미 정해져 넘어온 **앵커(anchor)**입니다. 그 뒤 좌표 4칸이 마침 sub-block 하나입니다.

```
앵커 확정:   cup | [M]   [M]   [M]   [M]
1회:        cup | <12>  [M]   [M]   <352>   ← 4칸 중 확신 높은 2칸. 오른쪽 끝이 먼저 확정될 수 있음
2회:        cup | <12>  <220> <93>  <352>
```

AR이라면 반드시 `<12>` → `<220>` → `<93>` → `<352>` 순서로 4번 호출해야 합니다.

**빈칸이 오른쪽 위치도 봅니다.** 블록 안 attention은 양방향이라 `<93>`을 고를 때 이미 확정된 `<352>`를 참고합니다. 아직 빈칸인 위치도 "그 자리에 뭔가 올 것"이라는 위치 정보는 보입니다.

**확정 개수를 모델이 정합니다.** 쉬운 구간(예: `<|box_end|>`, 쉼표 같은 구조 토큰)은 여러 칸이 한꺼번에 확정되고, 어려운 좌표는 1칸씩 갑니다.

#### ⑤ 왜 이렇게 AR 쪽으로 묶었나

- **sub-block을 크게 하거나 τ를 높여 더 병렬로 만들면 정확도가 무너집니다.** τ 1.0에서 COCO가 60.72 → 54.06으로 떨어집니다. 블록 크기 실험에서도 entropy 디코딩은 B=16이 B=32보다 좋았습니다.
- 서로 의존하는 좌표를 한꺼번에 확정하면, 각 칸은 그럴듯해도 조합이 어긋나는 문제가 생깁니다. 예를 들어 x1은 물체 A 기준, x2는 물체 B 기준으로 확정될 수 있습니다. 이를 막으려면 결국 조금씩, 앞쪽부터 가야 합니다.

**그래서 진짜 병렬 이득은 entropy 디코딩보다 self-speculative 쪽에서 나옵니다.** 확산으로 32칸 초안을 한 번에 쓰고 AR로 검산하면 TPF가 2.18까지 올라갑니다.

#### 한 줄 정리

**학습은 랜덤 마스킹, 추론은 확신도순 확정입니다. 하지만 블록 순서, sub-block 4칸 순서, 평균 1.37토큰/forward 때문에 실제 동작은 "4칸 창 안에서만 순서를 바꿔 가끔 몇 칸씩 건너뛰는 AR"에 가깝습니다.** "사실상 AR 아니냐"는 직관이 이 논문 설정에서는 상당 부분 맞습니다.

### Q8. "이미 잘 학습된 AR grounding 모델에 mask 토큰만 추가하고 확산 손실로 이어 학습한다"는 게 무슨 뜻?

*1.3절 도입부 한 문장이 너무 압축돼 있어서, 무엇을 물려받고 무엇이 새로 바뀌는지 풀어 둔다.*

**한 줄로:** 확산 모델을 백지에서 새로 만들지 않고, 이미 다 배운 AR 모델의 가중치를 그대로 가져와서 "빈칸 채우기"라는 새 답하는 법만 추가로 가르친다는 뜻입니다.

#### ① "처음부터 학습"이면 무엇을 다 배워야 하나

확산 grounding 모델을 백지에서 만들려면 아래를 모두 새로 익혀야 합니다.

| 배울 것 | 예 |
|:---|:---|
| 이미지 보기 | 컵이 어떻게 생겼는지, 어디 있는지 |
| 언어 이해 | "빨간 컵 왼쪽의 숟가락" 같은 문장 |
| 좌표 표현 | `<373>`이 너비의 37.3% 지점이라는 것 |
| 출력 문법 | `<|object_ref_start|>cup<|object_ref_end|><|box_start|>...` 순서 |
| **빈칸 채우기 방식** | 양쪽을 보며 [MASK]를 맞히기 |

- 위의 네 가지는 AR 모델이 이미 사전학습(700B 토큰 이상)과 좌표 학습으로 다 배운 내용입니다.
- 새로운 것은 맨 아래 한 줄, "답하는 방식"뿐입니다.
- 게다가 확산 언어모델은 같은 실력에 도달하는 데 AR보다 데이터와 계산을 더 먹는다고 알려져 있습니다. 백지에서 시작하면 그만큼 더 비쌉니다.

#### ② "이어 학습"이란 구체적으로

AR 모델의 학습이 끝난 체크포인트를 그대로 불러와 **추가 학습(continued training)**을 하는 것입니다. 바뀌는 것은 세 가지뿐입니다.

| 항목 | AR 모델 | 변환 후 | 바뀐 정도 |
|:---|:---|:---|:---|
| 시각 인코더·projector·36층 가중치 | 학습 완료 | **그대로 가져와 출발** | 이후 미세 조정 |
| 어휘 | 152,670개 | +`[MASK]` 1개 | 새 줄 하나 (Q2) |
| attention | 왼쪽만 봄 | 빈칸 블록 안에서는 양쪽 다 봄 | 마스크 규칙만 변경 (그림 4) |
| 손실 | 다음 토큰 맞히기 | 빈칸 맞히기 0.5 + 다음 토큰 맞히기 0.5 | 문제 유형 추가 |

**새로 생기는 가중치는 MASK 줄 하나(파라미터 5,120개)뿐입니다.** 나머지 48억 개 파라미터는 모두 AR 모델에서 물려받습니다. Transformer 구조 자체가 똑같기 때문입니다. 확산이냐 AR이냐는 "어디까지 보게 하고(attention mask), 무엇을 맞히게 하느냐(손실)"의 차이일 뿐입니다. 그래서 논문은 "확산은 Transformer 위의 생성 전략일 뿐"이라고 말합니다.

#### ③ 비유

글을 잘 쓰는 작가에게 **빈칸 채우기 퀴즈 푸는 법**을 가르치는 것과 같습니다.
- 어휘력, 문법, 세상 지식은 이미 있습니다.
- 새로 익힐 것은 "앞뒤 문맥을 보고 빈칸을 메우는 요령"뿐입니다.
- 퀴즈를 위해 갓난아기부터 다시 키울 필요는 없습니다.

#### ④ 이어 학습할 때 AR 손실도 같이 두는 이유

손실이 "빈칸 맞히기 0.5 + 다음 토큰 맞히기 0.5"인 이유입니다.
- 빈칸 맞히기만 시키면 원래 잘하던 "한 칸씩 쓰기" 실력이 무너질 수 있습니다(망각).
- 둘 다 시키면 한 가중치가 두 모드를 모두 유지합니다. 그래서 확산으로 초안을 쓰고 AR로 검산하는 self-speculative가 가능해집니다(Q3, 1.5절).

#### ⑤ 주의: "싸다"는 상대적입니다

변환도 결코 가볍지 않습니다. 공개 코드 기준으로 네 단계를 거칩니다.

| 단계 | 샘플 수 | 에폭 |
|:---|:---|:---|
| general | 약 300만 | 2 |
| specialist | 약 3,000만 | 2 |
| sft1 | 약 470만 | 1 |
| sft2 | 약 30만 | 1 |

논문 기준으로는 256 GPU를 썼습니다. "처음부터 사전학습(700B+ 토큰, 이미지 보기·언어·좌표를 전부 새로)"보다 싸다는 뜻이지, 몇 시간짜리 미세조정이라는 뜻은 아닙니다. 논문은 변환에 들어간 정확한 토큰 수나 GPU 시간을 밝히지 않습니다.

## 📌 한 줄 요약 (전체)

**AR grounding VLM을 블록 확산으로 변환해 좌표를 병렬로 채운 4.84B 모델. 구조·손실·디코딩은 코드와 정확히 맞고 DLM↔MTP 통제 실험은 정직하지만, 확산 모델이 AR 부모를 이긴 점수들은 평가 벤치마크 이름을 단 DLM 전용 SFT2 데이터와 겹쳐 오염이 강하게 의심되고, "2.56×/4.51× 가속"의 절반가량은 알고리즘이 아닌 실행 스택 차이다. 정확도는 VLM 쪽, 속도 주장은 직접 재측정 후 신뢰할 것.**
